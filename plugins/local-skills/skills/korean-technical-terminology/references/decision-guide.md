# 한국어 기술 용어 판단 가이드

이 문서는 고정 번역 사전이 아니다. 독자, 검색 가능성, upstream 표기, 대상 프로젝트와 도메인의 공식 한국어 용례를 함께 보고 용어를 결정하기 위한 기준이다. 한국어 기술 문서를 다루는 스킬이라는 언어 범위는 의도적이지만, 특정 프런트엔드 스택의 용어를 기술 전반의 정답으로 일반화하지 않는다.

## 3단계 판단

| 분류 | 적용 기준 | 예시 |
| --- | --- | --- |
| Canonical English | 제품명, 프로토콜·API 식별자, 코드 심벌, CLI 명령처럼 원어가 정확성과 검색 가능성을 보존할 때 | `Claude Code`, `Codex`, `HTTP`, `useEffect`, `git rebase` |
| Established Korean | 같은 프로젝트·도메인의 공식 한국어 문서나 유지되는 용어집에서 일관된 표기를 사용할 때 | React 용어집의 “생명주기·플러그인”, MDN의 “접근성 트리”처럼 출처 범위가 확인된 표기 |
| Natural rewrite | 사전식 직역이 어색하고 식별자나 정착 용어도 아닐 때 | 문맥상 “실패 클래스”가 분류를 뜻하면 “실패 유형”으로 바꾸는 식의 문장 단위 수정 |

예시는 문맥 판단을 돕기 위한 것이며 모든 문서에 같은 표기를 강제하지 않는다. 식별자는 분야와 무관하게 그대로 보존할 수 있지만, 번역 용례는 출처가 다루는 프로젝트와 도메인 밖으로 자동 확장하지 않는다.

## 범용성 경계

- 이 스킬의 범용성은 **한국어 기술 문서 전반에 적용할 판단 절차**에 있다. 모든 기술 분야에 통용되는 고정 용어 목록을 제공한다는 뜻이 아니다.
- 프로젝트가 관리하는 용어집은 해당 프로젝트에서 가장 강한 근거다. 다른 프로젝트에서는 다시 확인한다.
- 공식 한국어 문서 하나의 표기는 유력한 용례지만, 서로 다른 도메인에서 같은 번역을 강제할 충분조건은 아니다.
- 제품명·프로토콜·API·코드 심벌·CLI는 번역 빈도보다 upstream의 정확한 식별자를 우선한다.
- 공개 사용 빈도는 후보를 찾는 보조 자료다. 출처 범위, 문맥, 유지 상태를 대신하지 않는다.

## 조사 순서

1. upstream에서 제품명·API·프로토콜·코드 심벌·CLI인지 확인한다.
2. 대상 프로젝트가 관리하는 한국어 용어집이나 공식 한국어 문서를 확인한다.
3. 같은 도메인의 권위 있는 한국어 문서에서 문맥이 일치하는지 확인한다.
4. 공식 용례가 없을 때만 공개 커뮤니티 사용 빈도를 보조 근거로 본다.
5. 정확한 검색어가 중요하고 정착된 번역이 없으면 영어를 유지한다.
6. 제목, 표, 본문, FAQ에서 같은 개념의 표기를 통일한다.

공개 웹 조사가 필요하면 `agent-reach`의 public-only 경계를 지키고 공식 문서와 upstream 저장소를 우선한다.

## 범위가 확인된 공개 용례

아래 자료는 판단 방식과 출처 기록의 예시다. React 용어집은 React 문서에, MDN 용례는 웹 플랫폼 문맥에 우선 적용하며 기술 문서 전체의 고정 사전으로 사용하지 않는다.

- React 한국어 용어집은 `Lifecycle`을 “생명주기”, `Plugin`을 “플러그인”, `Reconciliation`을 “재조정”, `Markup`을 “마크업”으로 정한다.
  - https://github.com/reactjs/ko.react.dev/blob/dabd21bb52e2b9bb2c18c3622e42c6d303d1f2f9/wiki/translate-glossary.md
- React 한국어 문서는 optimistic update 문맥에서 “낙관적 업데이트”를 사용한다.
  - https://ko.react.dev/reference/react/useOptimistic
- MDN 한국어 문서는 “접근성 트리”와 “캐시 축출(cache eviction)”을 사용한다.
  - https://developer.mozilla.org/ko/docs/Glossary/Accessibility_tree
  - https://developer.mozilla.org/ko/docs/Web/HTTP/Guides/Caching
- web.dev 한국어 문서는 제품·지표군 이름 `Core Web Vitals`를 본문에서 유지하면서 설명은 한국어로 제공한다.
  - https://web.dev/articles/vitals?hl=ko

## 피할 것

- 기술 용어라는 이유만으로 정착된 한국어까지 전부 영어로 되돌리기
- 검색 가능한 canonical name을 근거 없이 새 한국어 조어로 바꾸기
- 한 문서에서 같은 용어를 영어, 음역, 번역어로 번갈아 쓰기
- 출처 하나의 번역을 모든 프로젝트에 보편 규칙처럼 강제하기
- 코드·CLI·파일명·패키지명을 번역하기
